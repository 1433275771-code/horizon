## [ChainDrop Worm Compromises Over 1,300 npm Packages in Supply Chain Attack](https://www.bleepingcomputer.com/news/security/massive-chaindrop-npm-supply-chain-attack-infects-hundreds-of-packages/) ⭐️ 9.0/10

ChainDrop, a self-propagating worm, has compromised more than 1,300 npm packages, including popular caching libraries Keyv and Cacheable, which collectively see 2 billion monthly downloads. Attackers breached the Keyv maintainer&\#x27;s GitHub account and published malicious versions via legitimate GitHub Actions workflows. This is one of the largest npm supply chain attacks to date, affecting millions of developers and downstream organizations. Because the affected packages are highly popular and the worm can self-propagate, any developer who installed an affected version must treat their system as compromised and rotate credentials immediately. The malicious install scripts setup.mjs and Math\_Symbol.js execute automatically during npm install, stealing credentials for GitHub, npm, AWS, and Kubernetes, and can republish malware to other maintainers&\#x27; packages. Security firms recommend treating affected systems as compromised, rotating all tokens, and using the npm-cache\[.\]com domain as a compromise indicator \(IOC\).

telegram · zaihuapd · Aug 5, 03:04

**Background**: npm is the default package manager for JavaScript and Node.js; developers run npm install to fetch dependencies, meaning malicious code in a package can execute automatically. A supply chain attack targets widely used open-source packages to spread malware downstream. In this attack, the worm used compromised maintainer accounts and legitimate CI/CD \(GitHub Actions\) builds to publish tainted versions while keeping provenance claims valid, making detection harder.

## [LLMs Can&\#x27;t Jump: Position Paper on AI Reasoning Limits](https://openreview.net/challenge?redirect=%2Fforum%3Fid%3DklU4737opt) ⭐️ 8.0/10

A position paper titled &quot;LLMs Can&\#x27;t Jump&quot; argues that large language models cannot make the creative &\#x27;jumps&\#x27; in reasoning required to generate novel explanatory hypotheses. The paper, shared on OpenReview, scored 8.0/10 and attracted 161 comments and 233 points in community engagement. This paper challenges optimistic claims that LLMs can drive scientific discovery or automate complex reasoning jobs, highlighting fundamental limitations rather than mere scaling or prompting issues. It has sparked significant debate about where AI research should focus and what realistic expectations for LLM reasoning should be. The core claim is that LLMs, which operate through lossy linguistic encoding of experience, can only interpolate within their training distribution and cannot perform the intuitive &\#x27;jump&\#x27; to new conceptual frameworks. Notably, author Tom Zahavy clarified in a community follow-up that the paper does not claim LLMs can never make real scientific discoveries, but rather that they cannot leap to novel hypotheses unaided.

hackernews · theanonymousone · Aug 5, 11:01 · [Discussion](https://news.ycombinator.com/item?id=49181083)

**Background**: Large language models generate text by predicting the next token based on statistical patterns in training data. Chain-of-thought prompting improves reasoning by eliciting explicit intermediate steps, while System 2 thinking refers to slow, deliberate logical reasoning, and compositional generalization is the ability to combine known components into novel combinations. This position paper focuses on the distinction between incremental step-by-step inference and the creative leap—the &\#x27;jump&\#x27;—that humans sometimes make when forming entirely new explanatory hypotheses.

## [LLM 0.32 adds reasoning traces, OpenAI Responses, server-side tools](https://simonwillison.net/2026/Aug/4/new-release-of-llm/#atom-everything) ⭐️ 8.0/10

Simon Willison released LLM 0.32, the project&\#x27;s most significant update since initial launch. It adds visible reasoning traces to stderr, support for the OpenAI Responses API and server-side tools like CodeInterpreter and WebSearch, new GPT-5.6 models, and redesigned content-addressable SQLite logs. This is a major upgrade for a widely-used CLI tool that developers and data scientists rely on to interact with large language models. Reasoning traces and server-side tools make it easier to inspect model behavior and run tool-augmented prompts from the terminal, while the redesigned logging improves debugging and reproducibility. Reasoning traces are written to standard error so they can be hidden from piped stdout, with a -R/--hide-reasoning flag; OpenAI&\#x27;s Responses API enables built-in server-side tools such as CodeInterpreter and WebSearch, and the llm-anthropic plugin adds WebFetch, CodeExecution and AnthropicMCP. The new &\#x27;llm openai endpoint&\#x27; command runs one-off prompts against any OpenAI-compatible endpoint without logging.

rss · Simon Willison · Aug 4, 23:58

**Background**: LLM is an open-source command-line tool by Simon Willison that provides a uniform interface for running prompts against many different large language models, including OpenAI, Anthropic and local models. Reasoning traces are step-by-step chain-of-thought outputs produced by modern reasoning models, which were traditionally hidden; exposing them to stderr gives users insight into how a model reached an answer. The OpenAI Responses API, released in March 2025, is a newer API that supports stateful interactions and built-in tools such as web search and code execution. SQLite is used by LLM for logging; content-addressable storage stores logs based on a hash of their content, which helps avoid duplicates and enables efficient queries.

## [ByteDance&\#x27;s SeedRealtime full-duplex audio-video model launches in Doubao](https://seed.bytedance.com/zh/blog/seedrealtime-%E9%9F%B3%E8%A7%86%E9%A2%91%E5%85%A8%E5%8F%8C%E5%B7%A5%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%8F%91%E5%B8%83-%E8%B5%B0%E5%90%91%E5%85%A8%E6%A8%A1%E6%80%81%E8%87%AA%E7%84%B6%E4%BA%A4%E4%BA%92) ⭐️ 8.0/10

On August 5, ByteDance launched SeedRealtime, a native audio-video full-duplex large model that integrates audio, video, and text in a unified architecture. The model has been fully rolled out in the Doubao app, enabling real-time multimodal interaction without traditional ASR-VLM-TTS module chaining. This is a significant step toward natural real-time human-AI interaction, cutting latency and conversational glitches compared to cascaded systems. It signals an industry shift from modular speech pipelines to end-to-end multimodal models, potentially affecting competitors like OpenAI, Google, and Meta in the voice AI space. End-to-end human evaluation showed SeedRealtime reduces audio-video conversation rhythm issues by half compared with cascaded models, and significantly cuts interruptions like being cut off mid-sentence. The model does not need an external VAD for turn-taking, supporting simultaneous &\#x27;watch, listen, and speak&\#x27; operation.

Notable details include the animated WebP decoder/demuxer, a Vulkan-compute-based v360\_vulkan filter covering popular 360-degree formats, and a Playdate encoder/muxer targeting the handheld device&\#x27;s 1-bit 400x240 display and PDV format. The ONNX Runtime DNN backend, contributed by AMD, enables AI model inferencing inside FFmpeg using GPUs and NPUs, while the Claude-assisted process was specifically used for locating missing backports rather than writing core code.
